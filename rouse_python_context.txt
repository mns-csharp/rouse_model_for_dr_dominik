================================================================================
ROUSE MODEL VALIDATION PROMPT FOR SURPASS-ALPHA CG FRAMEWORK
================================================================================

OBJECTIVE
=========

Prove that the surpass-alpha coarse-grained (CG) representation:

  1. Fully abides by ALL Rouse static and dynamic properties listed in:
       Kuriata, A., Gront, D. & Sikorski, A., CMST 22(4), 179-185 (2016)

  2. Determines WHICH properties from the original Rouse paper:
       Rouse, P.E. Jr., J. Chem. Phys. 21(7), 1272-1280 (1953)
     are met by surpass-alpha, and which are NOT met, with quantitative
     justification for every conclusion.

No hand-waving. No skipping. No "approximately done". Every property either
passes with a measured exponent, or fails with a documented reason.


CONTEXT
=======

surpass-alpha is an off-lattice coarse-grained polymer simulation framework
using Monte Carlo moves. The Rouse model describes the dynamics of a Gaussian
chain of N beads connected by harmonic springs, each bead experiencing
independent Langevin friction. With athermal excluded volume added, the chain
becomes a self-avoiding walk (SAW), and the dynamic exponents shift from ideal
Rouse to SAW-Rouse values.

The Kuriata 2016 paper validated a bead-spring Rouse model and a backrub model
against the same properties we must validate here for surpass-alpha.


INPUTS
======

  Simulation Parameters:
    Chain lengths:        N = 25, 50, 100, 250, 500
    Volume fraction:      phi = 0.035 (constant for all N)
    Excluded volume:      contactEnergy = 0, RepulsiveEnergy = 1e6 (athermal)
    MC moves:             Segmented hinge + N-tail + C-tail (local) + pivot (global)
    Bond spacing:         l0 = 1.5 * sigma = 5.7 A  (sigma = 3.8 A)
    Temperature:          300 K
    Initialization:       Random walk for all chain lengths
    Backend:              CPU only (CellListSegmentedEnergyComputer + CaContactKernel)

  Chain Counts and Sweep Schedule:
    +-----+--------+-----------+-------------+---------+-------+
    | N   | Chains | Eq Sweeps | Prod Sweeps | Box (A) | phi   |
    +-----+--------+-----------+-------------+---------+-------+
    |  25 |    500 |     2,000 |       5,000 |   269.6 | 0.035 |
    |  50 |    500 |     5,000 |       5,000 |   339.7 | 0.035 |
    | 100 |    500 |     5,000 |       5,000 |   428.0 | 0.035 |
    | 250 |    200 |    10,000 |       5,000 |   428.0 | 0.035 |
    | 500 |    110 |    25,000 |      10,000 |   441.8 | 0.035 |
    +-----+--------+-----------+-------------+---------+-------+

  Reference Theoretical Values:
    Static:   2nu = 1.18 (SAW), ratio R2/Rg2 = 6.25 (SAW), 6.0 (ideal)
    Dynamic:  g_CM exponent = 1.00, g1 short-time exponent = 0.50,
              D exponent = -1.00, tau_R exponent = 2.18 (SAW)

  For each N in {25, 50, 100, 250, 500}:

    Step 1.1  Initialize the surpass-alpha system:
                - Random walk chain initialization
                - Box size as specified in the table
                - Athermal excluded volume parameters

    Step 1.2  Run equilibration for Eq_Sweeps sweeps.

              g1(t) = < |r_{N/2}(sweep) - r_{N/2}(0)|^2 >
              Average over all chains.
                -> fig2_seg20_msd_N{N}_s42.tsv  (columns: sweep, g1)

    Step 1.5  Compute MSD of center of mass:
              g_CM(t) = < |r_CM(sweep) - r_CM(0)|^2 >

              g_R(t) = < R(0) . R(sweep) > / < R^2 >

AGENT ARCHITECTURE
==================

  WORKER AGENTS (5 agents running in parallel)
  --------------------------------------------
  - At the START of each iteration, each Worker Agent declares in
    iteration_log.txt the EXACT list of requirement IDs it promises
    to complete this iteration. Example:
      [ITER 1] [WORKER-A] [PROMISE] Will complete: REQ-01, REQ-03, REQ-07

  - Workers execute their promised requirements and mark each [DONE]
    in requirements_list.md upon verified file creation.

  - Workers are forbidden from marking a requirement [DONE] without
    the corresponding output file existing on disk.

  - Workers log completion:
      [ITER 1] [WORKER-A] [DONE] REQ-01: fig_R2_vs_N.png written to 01_static_properties\

  - Workers log failures honestly:
      [ITER 1] [WORKER-A] [FAIL] REQ-07: fit diverged, raw data in 05_data\N500\fig3...tsv


  SUPERVISOR AGENT
  ----------------
  - Monitors all 5 Worker Agents during each iteration.
  - After each Worker completes a promise, Supervisor:
      (a) Checks that the file actually exists on disk.
      (b) Checks that requirements_list.md is updated to [DONE].
      (c) Checks that iteration_log.txt has the completion entry.
  - If any check fails, Supervisor logs:
      [ITER 1] [SUPERVISOR] [VIOLATION] WORKER-A claimed REQ-01 done but file missing.
    and resets that requirement to [TODO].
  - Supervisor is NOT allowed to skip checks to save time.
  - Supervisor reports to Manager at end of each iteration:
      [ITER 1] [SUPERVISOR] [REPORT] X requirements verified done, Y violations found.


  MANAGER AGENT
  -------------
  - Monitors the Supervisor Agent.
  - After Supervisor's end-of-iteration report, Manager:
      (a) Independently spot-checks 20% of [DONE] items by verifying
          file existence and content validity (file not empty, correct columns).
      (b) If Manager finds a [DONE] item that is invalid, Manager logs:
            [ITER 1] [MANAGER] [ESCALATION] Supervisor failed to catch invalid
            completion of REQ-07. Resetting to [TODO].
          and resets it to [TODO].
      (c) If Supervisor skipped checks, Manager flags:
            [ITER 1] [MANAGER] [WARNING] Supervisor skipped verification of WORKER-C.
  - Manager does NOT execute requirements directly.
  - Manager logs its assessment:
      [ITER 1] [MANAGER] [ASSESSMENT] Supervisor performance: adequate / inadequate.


  TIMEKEEPER AGENT
  ----------------
  - Runs at the END of each iteration.
  - Reads requirements_list.md and counts [TODO] vs [DONE].
  - Reads iteration_log.txt and verifies every PROMISE from this iteration
    has a matching DONE or FAIL entry from the same Worker.
  - If any promise is unaccounted for (neither DONE nor FAIL), Timekeeper
    treats it as [TODO] and logs:
      [ITER 1] [TIMEKEEPER] [UNACCOUNTED] WORKER-B promised REQ-12 but no outcome logged.
  - Decision logic:
      IF all items in requirements_list.md are [DONE]:
        Log: [ITER 1] [TIMEKEEPER] [COMPLETE] All requirements done. No further iteration.
        Halt.
      ELSE:
        Log: [ITER 1] [TIMEKEEPER] [CONTINUE] {count} requirements remain. Starting ITER 2.
        Start next iteration.
  - Timekeeper does NOT give extensions or accept excuses.
  - Timekeeper is not allowed to declare completion if any [TODO] items remain.


  SENTINEL AGENT
  --------------
  - Runs continuously throughout every iteration (not just at the end).
  - Enforces CONSTRAINT C1 at all times: scans the project directory
    for any file not in the approved deliverable structure and not named
    iteration_log.txt or requirements_list.md.
  - If an unauthorized file is found:
      [ITER 1] [SENTINEL] [VIOLATION] Unauthorized file found: tmp_debug.tsv. Deleting.
    and deletes it immediately.
  - Also enforces C2: if a Worker marks [DONE] in requirements_list.md,
    Sentinel verifies the file exists before the mark is accepted.
  - Sentinel reports a violation summary to Manager at end of each iteration.


ITERATIVE PROCESS
=================

  Loop structure:

    iteration = 1
    WHILE any requirement in requirements_list.md is [TODO]:

      LOG: [ITER {iteration}] [TIMEKEEPER] [START] Beginning iteration {iteration}.

      -- WORKER PHASE --
      Each of 5 Worker Agents:
        1. Reads requirements_list.md for all [TODO] items.
        2. Claims a non-overlapping subset (no two workers claim the same req).
        3. Declares promises in iteration_log.txt.
        4. Executes requirements.
        5. Marks completed items [DONE] in requirements_list.md.
        6. Logs DONE or FAIL for each promise.

      -- SENTINEL PHASE (continuous) --
      Sentinel monitors file creation throughout the worker phase.

      -- SUPERVISOR PHASE --
      Supervisor verifies all Worker completions.
      Logs REPORT to iteration_log.txt.

      -- MANAGER PHASE --
      Manager spot-checks Supervisor's work.
      Logs ASSESSMENT to iteration_log.txt.

      -- TIMEKEEPER PHASE --
      Timekeeper counts remaining [TODO] items.
      Checks all promises are accounted for.
      Decides: COMPLETE or CONTINUE.

      iteration += 1

    END WHILE
